# JUCE Plugin Brief Template
## Version 1.0

Use this template at the start of every new plugin project. It captures the decisions that shape the codebase architecture before any code is written, and explicitly defers creative decisions until after the DSP is working and audible.

### How to use

1. **You fill out Section 1** before the agent writes any code (~10-15 minutes)
2. **Agent generates a spec** from Section 1 (signal flow, architecture, proposed parameters)
3. **You review Section 2** items as the agent proposes them during implementation
4. **You fill out Section 3** after loading the plugin in your DAW and listening

Items marked `[HUMAN_ONLY]` must never be assumed or generated by the agent. The agent must stop and ask.

# Agent Instructions

When this brief is provided at the start of a plugin project:

1. **Validate Section 1 completeness.** If any architecture decisions are missing, ask before proceeding. Do not assume signal flow, I/O format, or feedback topology.

2. **Generate a spec from Section 1.** Include: detailed signal flow diagram, processBlock pseudocode, proposed parameter table (Section 2.1), proposed GUI layout (Section 2.2), and a validation checklist (Section 2.3). Present for human approval before writing code.

3. **Implement with standard safety patterns:**
   - `juce::ScopedNoDenormals` in processBlock
   - `juce::SmoothedValue` for all automatable parameters (20ms default ramp)
   - Smooth bypass/freeze transitions (~42ms / 512 samples at 48kHz)
   - Output limiter (tanh or equivalent soft clip)
   - No heap allocation in processBlock
   - No locks on the audio thread
   - Full `getStateInformation` / `setStateInformation` implementation (never leave as stubs)
   - Mono-to-stereo input handling
   - Sample-rate-dependent coefficient recalculation in prepareToPlay

4. **Stop at Section 3 gates.** When the build is functional, tell the human to load it in their DAW and listen. Do not generate preset names, preset values, GUI colors, or sonic descriptions. Wait for human input.

5. **Run the validation checklist** (Section 2.3) before declaring the build complete. Report results.

6. **Build verification order:**
   - Compile succeeds
   - Loads in target DAW without crash
   - Audio passes through (bypass test)
   - Each parameter moves without clicks or artifacts
   - State save/restore round-trip
   - Sample rate and buffer size stress test
   - Human listening session (Section 3)
   - Preset implementation (after Section 3 is filled)
   - Final build and release

# Appendix: Common DSP Module Reference

When filling in Section 1.2 (DSP modules), these are common building blocks. Not exhaustive — combine and customize as needed.

## Effects

| Module | What it does | Key parameters | JUCE classes |
|---|---|---|---|
| Delay | Time-based echo | time, feedback, mix | juce::dsp::DelayLine |
| Reverb | Diffuse spatial effect | decay, damping, size | Custom FDN or juce::dsp::Reverb |
| Chorus/Flanger | Modulated short delay | rate, depth, feedback | juce::dsp::DelayLine + LFO |
| Phaser | Modulated allpass chain | rate, depth, stages | Custom allpass cascade |
| EQ (parametric) | Frequency shaping | freq, gain, Q per band | juce::dsp::IIR or custom TPT |
| EQ (shelving) | Low/high shelf | freq, gain | juce::dsp::IIR |
| Compressor | Dynamic range reduction | threshold, ratio, attack, release | juce::dsp::Compressor or custom |
| Limiter | Brick-wall peak control | threshold, release | juce::dsp::Limiter |
| Gate | Silence below threshold | threshold, attack, release | Custom envelope follower |
| Distortion | Waveshaping/saturation | drive, mix, type | Custom waveshaper |
| Wavefolder | Harmonic folding | drive, folds | Custom: sin(x*foldAmt*pi)/foldAmt |
| Bitcrusher | Bit depth/rate reduction | bits, rate | Custom sample-and-hold |
| Filter (SVF) | LP/HP/BP/notch | cutoff, resonance, type | Custom Cytomic TPT SVF |
| Envelope follower | Amplitude tracking | attack, release | Custom one-pole filters |
| Pitch shifter | Frequency transposition | semitones | Custom granular or FFT |
| Granular | Buffer scrambling | grain size, density, chaos | Custom circular buffer |
| Stereo widener | Spatial manipulation | width | Mid/side matrix or per-line panning |

## Instruments (synthesizers)

| Module | What it does | Key parameters | JUCE classes |
|---|---|---|---|
| Oscillator | Tone generation | waveform, pitch, detune | juce::dsp::Oscillator |
| Wavetable | Table-scanning synthesis | position, waveform set | Custom with interpolation |
| FM operator | Frequency modulation | ratio, index, feedback | Custom sine + modulation |
| Noise | Noise generation | color (white/pink/brown) | juce::Random |
| ADSR | Amplitude envelope | attack, decay, sustain, release | juce::ADSR |
| Voice allocator | Polyphony management | voices, steal mode | juce::Synthesiser |
| Unison | Detuned voice stacking | voices, detune, spread | Custom per-voice detuning |
| Portamento | Pitch glide | time, mode (always/legato) | Custom smoothed pitch |

## Utility

| Module | What it does | Key parameters | JUCE classes |
|---|---|---|---|
| Level meter | Signal level display | peak/RMS, decay | Custom with atomic values |
| Spectrum analyzer | Frequency display | FFT size, overlap | juce::dsp::FFT |
| Tuner | Pitch detection | reference freq | Custom autocorrelation or FFT |
| Crossover | Frequency band split | crossover frequencies | Linkwitz-Riley filter pairs |
| Mix bus | Parallel blend | levels per path | Gain + summing |
| DC blocker | Remove DC offset | cutoff (~5Hz) | One-pole highpass |
