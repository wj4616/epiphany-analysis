### I01 — Specify `populate()` return-value as a discriminated union
**source_section:** Headline Insight (HI-1) + Alternative Hypotheses (AH-1)
**target_section:** `<kb_scope>` interface contract definition (line ~73-79)
**observation:** Node A specifies `populate(content, tier, metadata) → status` but does not constrain the shape of `status`. RAG_MCP returns a manifest artifact while text KBs return a write status. A uniform-treating caller silently mishandles RAG_MCP (H-CONS1, confidence 0.88).
**idea:** Replace the unspecified `status` return with an explicitly tagged discriminated union: `{kind: "write_status", success: bool, written_count: int, errors: []}` for write-capable adapters; `{kind: "manifest", manifest_path: str, items: [...]}` for RAG_MCP. Document the constraint that callers MUST switch on `kind` before consuming the rest of the payload.
**category:** content
**effort:** low
