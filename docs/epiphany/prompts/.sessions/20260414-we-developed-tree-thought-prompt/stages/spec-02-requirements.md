# spec-02-requirements.md

Output of MSPEC12 Phase 2 — Requirement Extraction (S4).
Classifications: SHALL (mandatory), SHOULD (recommended), MAY (optional).
Every requirement links back to the source line(s) in `00-input.md` and/or the
decomposition element from `spec-01-domain.md`. Ambiguities are flagged `→ OQ-N`
for downstream S6 completeness audit.

Domain-gap-inferred requirements are tagged `[domain-inferred]`.

## Functional Requirements (FR)

### FR-1 — Accept original input as node A (SHALL)
The system SHALL accept a user-provided original input and store it verbatim as node A,
without mutation, regardless of whether the input is delivered inline in the user prompt,
as a file path, or in another user-provided format.
Source: 00-input.md lines 11–14 ("store original context provided by user into node A";
"node a is the input. it could be specified directly in the user prompt context, or be
stored in a file or other format provided by the user").
Decomposition link: Core Elements → Node A.
Verification: after ingestion, a byte-wise comparison of node A against the supplied
input returns equal.
Ambiguity: exact list of accepted "other formats" is unspecified → OQ-14.

### FR-2 — Accept analysis as node B (SHALL)
The system SHALL accept an analysis document describing node A and store it verbatim
as node B, preserving provenance metadata including whether it was produced by
epiphany-genius.
Source: 00-input.md line 15 ("node b is the analysis document"); lines 66–67 (detect
epiphany-genius provenance).
Decomposition link: Core Elements → Node B; Epiphany-genius detection probe.
Verification: node B content equals supplied analysis content verbatim; a provenance
flag `from-epiphany-genius` is present and boolean-valued.

### FR-3 — Produce full analysis A1 of node A (SHALL)
The system SHALL produce node A1, a full analysis of node A, in which every detail,
concept, idea, facet (large, small, and fine), and technical specification is reviewed
and recorded; the system SHALL NOT generalize or gloss over any detail.
Source: 00-input.md lines 16–18 ("phase 0: analyze both nodes in full, taking into
account every details concept idea facet large small or fine, including technical
details, do not generalize or glaze over details").
Decomposition link: Core Elements → Node A1.
Verification: a coverage sweep shows every numeric value, file path, API name, code

### FR-4 — Produce full analysis B1 of node B (SHALL)

## Non-Functional Requirements (NFR)
